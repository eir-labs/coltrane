## Per-test verdict + rootcause hypothesis

### `sub_thread.solo_dev.spec.ts` (1 fail / 2 pass)

| # | Test | Verdict |
|---|---|---|
| 1 | hard: 3-parallel children return session_ids; recorder captures all 3 | **FAIL** |
| 2 | hard: each child --resumes with coherent follow-up | PASS |
| 3 | soft: <30s timing budget + distinct outputs | PASS |

**Failure 1 rootcause hypothesis:** Claude CLI assigns and returns session_ids correctly
(stream-json contains them), but coltrane-oss has no recorder hook for sub-thread turns —
the harness's `.coltrane-recorder.jsonl` is empty after the run. Coltrane's `MemoryLedger`
is in-process to a gig dispatch; sub-thread turns invoked at the CLI layer never reach it.
Smallest fix: wire a file-backed `SubthreadRecorder` keyed on session_id that observes
the MCP transport and appends per-turn entries.

### `sub_thread.platform_team.spec.ts` (2 fail / 1 pass)

| # | Test | Verdict |
|---|---|---|
| 1 | hard: same input two runs → same hash-sealed record | PASS (vacuously — both runs produce empty recorder, hashes match) |
| 2 | hard: --resume across API-version-bump fails CLOSED | **FAIL** |
| 3 | soft: observability_log monitoring hooks non-empty | **FAIL** |

**Failure 2 rootcause hypothesis:** No API-version concept exists on the MCP server.
`COLTRANE_API_VERSION` env var has no effect; resume across an injected version-bump
succeeds silently, which is the exact "silent corruption" risk this test was written
to surface. Smallest fix: add an `api_version` field to the MCP `initialize` handshake;
on `--resume`, compare against the originally-recorded version; emit a typed
`api_version_mismatch` error on divergence.

**Failure 3 rootcause hypothesis:** Same as solo_dev Failure 1 — no sub-thread recorder.
The "platform team" persona's monitoring contract requires structured per-turn entries
(`gig_id`, `run_fingerprint`, `session_id`); none exist. Coltrane's recorder is
gig-scoped; sub-thread-scoped recorder is missing.

> NOTE: The first platform_team test (hash-stability) passes for the WRONG reason —
> both runs hash an EMPTY recorder file (`SHA256("[]") == SHA256("[]")`). Once the
> recorder is wired (fixing F1/F3), this test will likely FAIL because Claude's
> output text varies run-to-run. The hash assertion needs to scope to deterministic
> fields (genome_hash, run_fingerprint, tool_call sequence) — not raw assistant text.

### `sub_thread.research_lab.spec.ts` (2 fail / 1 pass)

| # | Test | Verdict |
|---|---|---|
| 1 | hard: --resume chain length 5 produces identical hash-sealed record | PASS (vacuously — empty recorder both runs) |

| 3 | soft: trace tree renderable from recorder | **FAIL** |

**Failure 4 rootcause hypothesis:** No `parent_session_id` lineage seal anywhere in
coltrane. Claude CLI's stream-json includes session_id per turn, but not parent-child
edges across nested sub-threads (one Claude session spawning a child session). Coltrane

parent's session_id must be passed through as a `parent_session_id` field in the child's
first recorded turn. Smallest fix: thread `parent_session_id` through `makeClaudeInvoker`
+ record it.

**Failure 5 rootcause hypothesis:** Same upstream — no recorder, no lineage, nothing
to render as a tree.

> NOTE: Same vacuous-pass risk as platform_team F1 applies to research_lab F1

## One-paragraph honest read: "smallest fix to get >50% green"

The dominant failure mode (4 of 5 RED) is **the missing sub-thread recorder**. Coltrane
has a gig-scoped `MemoryLedger` but no file-backed recorder that observes per-turn MCP
traffic at the CLI sub-thread layer. Implementing a `SubthreadRecorder` (jsonl, keyed
on session_id, capturing `parent_session_id`, `turn_idx`, `tool_calls[]`,
`run_fingerprint`, `started_at`/`finished_at`) would unlock solo_dev F1,
platform_team F3, research_lab F4, and research_lab F5 — four of the five RED tests
in one move. The remaining fifth (platform_team F2, API-version fail-closed) is an
independent ~50-line change to the MCP `initialize` handshake. With both, the e2e
suite goes from 7/12 to ~11/12. The remaining gap (platform_team F1 and research_lab F1
"vacuous-pass") is the deeper one: making sub-thread output deterministic enough to
hash-equal across runs, which requires either deterministic-mode Claude invocation or
hash-scoping to provenance fields rather than free-form assistant text. That's
research-lab-grade work, properly scoped as a separate phase.

## Sub-thread maturity verdict

**Coltrane's sub-thread invocation maturity is at the "single-shot works, multi-turn
observability is missing" stage** — the CLI cage is correct (claude_invoker.ts
buildInvokerArgs is honest), but the substrate-of-truth seam for sub-thread turns is
not yet sealed. The eng-manager onboarding ramp is production-shaped; the platform-team
observability + research-lab determinism contracts need the recorder + lineage work.
