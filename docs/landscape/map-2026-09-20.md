## law-markup

- Akoma Ntoso / OASIS LegalDocML · **adopt** · active
  XML vocabulary for parliamentary, legislative and judicial documents (bills, acts, debates, judgments, amendments, collections); includes FRBR-based URI naming convention for point-in-time version addressing and a metadata model for lifecycle, temporal data, and references
  _why:_ AKN is the OASIS international standard for legislative document structure, providing FRBR-based URI naming (FRBRuri, FRBRthis, FRBRdate) for point-in-time law identification. It is the cross-jurisdictional alignment layer that USLM (US) and e-Gov (Japan) both overlap with, enabling uniform law citation across jurisdictions (cq-002). Its act/article/portion model also informs the source sublayer of clause decomposition (cq-001). Version 1.0 is the current OASIS Standard; v2.0/AKN 3.1 was in public comment at run time.
  https://www.oasis-open.org/standard/akn-v1-0/
- United States Legislative Markup (USLM) · **adopt** · active
  XML information model for US federal legislative documents including the US Code, bills, resolutions, statutes, and public laws; supports hierarchical document structure, positive-law codification, and stylistic variants (OLC, USC)
  _why:_ USLM 2.1.0 is the authoritative GPO XML schema for the US Code, bills, resolutions, and public laws. It directly provides versioned, addressable US federal primary law required by cq-002. The GitHub-hosted schema is the definitive source for positive-law codification structure and stylistic variants used by Congress.
  https://github.com/usgpo/uslm
- e-Gov 法令API / 法令標準XMLスキーマ (Japan Law XML Schema and API) · **adopt** · active
  XML schema (XSD) and HTTP API for Japanese primary law (statutes, cabinet orders, ministerial ordinances, notifications); provides full-text retrieval, article-level access, amendment history retrieval, and point-in-time versioning added in API v2
  _why:_ The Japan Digital Agency's e-Gov XML schema (XMLSchemaForJapaneseLaw_v3) and API v2 (released 2025-03-14) provide full-text retrieval, article-level access, amendment history, and point-in-time versioning for Japanese statutes, cabinet orders, and ministerial ordinances. This is the authoritative structured source for Japanese primary law (cq-002), directly relevant to the GK entity's governing jurisdiction.
  https://laws.e-gov.go.jp/docs/law-data-basic/419a603-xml-schema-for-japanese-law/
- Crown Legislation Markup Language (CLML) · **reference** · active · Crown copyright
  XML dialect for UK primary and secondary legislation published on legislation.gov.uk, covering acts, statutory instruments, explanatory notes, impact assessments, and point-in-time historical versions accessible via the legislation API
  _why:_ UK law is outside the primary jurisdiction scope (Japan, Delaware, US federal). However, CLML v2.6 is the most mature public implementation of historical-version access at article level with a documented API, and serves as a design reference for how to implement point-in-time versioning for our Japan and US law layers. Retained as a reference pattern, not as a data source.
  https://legislation.github.io/clml-schema/
- Formex (Formalized Exchange of Electronic Publications) v4 · **ignore** · active
  XML-based format for EU Official Journal publications including regulations, directives, decisions, and other EU legislative acts; defines logical markup for exchange between the Publications Office and contractors; most EUR-Lex documents with structured text are available in Formex
  _why:_ Formex is specific to EU Official Journal publications. EU law is outside the primary jurisdiction scope, and the potential Austrian entity was not included in the charter's primary scope. Formex provides no coverage for Japan, Delaware, or US federal law and is therefore not relevant to any charter need.
  https://op.europa.eu/en/web/eu-vocabularies/formex

## provenance

  _why:_ PROV-O (W3C Recommendation 2013) provides the OWL ontology for expressing provenance — entities, activities, agents, derivation chains (prov:wasDerivedFrom), and attribution (prov:wasAttributedTo).   _why:_ GLEIF LEI (ISO 17442:2020) provides globally unique, persistent 20-character codes for legal entities with Level 1 (entity identity) and Level 2 (ownership/relationship structure) data freely accessible via the Global LEI Index.
